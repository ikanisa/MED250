# Prescription retention cleanup

This private scheduled Edge Function removes draft, broadcast, cancelled, and expired request files once the order's `expires_at` has been past for 24 hours; timed-out selected requests are eligible 24 hours after selection, and completed requests after 30 days. It automatically expires selected requests at that 24-hour selection boundary, ending pharmacy prescription/contact access and freeing the customer to start another request.

Referenced cleanup is path-scoped rather than order-scoped. A service-only SQL RPC selects only paths whose complete reference set is outside retention, locks every selected path before its order rows, and creates a 15-minute durable lease. The order trigger, `dawanear_create_order`, and owner Storage insert/delete policies use the same advisory lock, so an object name cannot be replaced while referenced or claimed. Bucket-scoped restrictive policies make those checks mandatory even if the shared project already has broader permissive Storage policies, and client UPDATE/upsert is denied for the prescription bucket. After the Storage API confirms deletion, a second service-only RPC rechecks the complete reference set, clears all eligible terminal references atomically, and releases the lease. Storage or response ambiguity leaves the lease and database references in place. A recovery RPC scans expired claims independently of both order and object enumeration, retries actionable work, and removes claims that have neither a remaining object nor a reference. Each invocation reserves independent batch capacity for recovered and newly due paths, preventing a permanently failing retry set from starving new cleanup.

The function also recursively paginates Storage, rotates work through a service-only maintenance cursor, caps per-folder contributions, and sweeps uploads older than 24 hours that are not referenced by any order. Orphan candidates use a separate service-only claim that takes the same path lock as order creation, rechecks the Storage timestamp, and proves there is still no committed order before deletion. This closes the cutoff race with an in-flight order transaction. The sweep covers interrupted or ambiguous submissions without allowing referenced files or a large early-folder backlog to starve later folders.

Set a strong `DAWANEAR_CRON_TOKEN` secret and invoke the function with `POST` plus `X-DawaNear-Cron-Token`. The batch size defaults to 50 and is capped at 200. Schedule it only after the DawaNear migration has been applied and the retention periods have been approved in the production privacy policy.

`supabase/config.toml` disables the gateway JWT check for this function because the handler performs its own dedicated-token authentication. Deploy with that configuration intact.

Selected requests remain accessible only during the documented 24-hour selection window. The function transitions timed-out selections to `expired`, notifies recipients, then submits the shared path to the same protected cleanup flow.
